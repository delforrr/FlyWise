```sql
SELECT c.relname, n.conname, pg_get_constraintdef(n.oid)
FROM pg_constraint n
JOIN pg_class c ON c.oid = n.conrelid
JOIN pg_namespace s ON s.oid = c.relnamespace
WHERE s.nspname = 'public' AND n.contype = 'c'
ORDER BY c.relname, n.conname;
```

La revisión adversarial encontró una diferencia vigente en códigos opcionales. La carga protege códigos existentes ante datos de proveedor malformados y la edición HTTP valida lo introducido explícitamente. La prueba `validation.e2e-spec.ts` protege ese comportamiento. OpenFlights, OurAirports y los DTO administrativos comparten los patrones de códigos de aeropuerto y aerolínea. La ingesta descarta el valor inválido; cuando el proveedor lo configura como obligatorio, descarta y audita la fila. En la edición HTTP, un valor inválido produce 400. La prueba de edición y la de importación verifican el mismo criterio de validez y sus respuestas de entrada. Se comparten también los límites de escalas y la regla de extremos distintos.

## Límites y recuperación

No conexión arbitraria de APIs sin adaptador; credenciales por referencia.
Conservar cambios ajenos. Una reversión de código no autoriza pérdida de datos; migraciones requieren procedimiento validado en instancia separada. No push, merge ni acciones destructivas sin autorización explícita.

## Handoff de cierre

Registrar commit/base verificada, cambios, decisiones concretadas, comandos/resultados, hallazgos adversariales y dependencias desbloqueadas. Si hay bloqueo externo, describirlo sin marcar aceptación como cumplida. Mantener este ticket pendiente hasta reunir evidencia.

## Evidencia de la rama

Base T10 `ee39190`. El panel Servicios conserva el editor de correspondencias CSV y permite configurar OAG por mes y uno o más tramos, o BTS por mes completo. La ejecución guarda una instantánea y el archivo conserva las referencias del historial. Los servicios nuevos empiezan pausados. La programación unificada sigue en T13. Actividad ANAC se abre desde Indicadores.

La revisión independiente detectó la pérdida de la referencia al reintentar OAG o BTS, la lectura del tramo principal desde la API OAG anterior y la omisión de publicaciones históricas sin ID de ejecución en el selector de autorización. Los reintentos conservan el servicio y el alcance original, con las autorizaciones vacías para la nueva ejecución. La API OAG anterior reconoce el tramo principal de una configuración nueva. El selector presenta las fuentes vigentes aun cuando provienen de una métrica histórica mixta.

Pasaron `npm run build` y las pruebas de ambos proyectos (210 backend, 229 frontend), además de `npm run lint` en backend. El gate E2E pasó en siete suites y ocho pruebas, con PostgreSQL y Redis locales, una base descartable, respuestas OAG sintéticas, ZIP BTS sintéticos y los archivos fijados de OpenFlights. La suite de servicios cubre proveedor inválido, rechazo de credenciales literales, autorización histórica, ejecución, conflicto, reintento, archivo e historial. La suite de pipelines comprueba las correspondencias del catálogo.

Chromium verificó el build de producción con API simulada a 1440, 1024, 768 y 390 px. Se comprobó el HTML de SSR, la apertura y el cierre por teclado y el selector de proveedor. A 390 px se creó un servicio, se confirmó un cambio de fuente y se consultó el historial de la ejecución. El recorrido no mostró desborde horizontal ni errores de consola o hidratación. T12, T13 y T14 ya pueden usar este CRUD.

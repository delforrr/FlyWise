## Actualización y recuperación

La instalación limpia usa el contrato actual. Para ensayar una actualización, restaurar un respaldo de la versión anterior en una instancia separada, detener los escritores de esa instancia y usar clientes PostgreSQL compatibles con el servidor. Desde `backend/`, emitir el contrato con `npx prisma contract emit`, aplicar `psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f prisma/changes/20261115_recorte_actividad_anac.sql`, ejecutar `npx prisma db verify --schema-only --db "$DATABASE_URL"`, firmar con `npx prisma db sign --no-advance-ref --db "$DATABASE_URL"` y verificar con `npx prisma db verify --db "$DATABASE_URL"`.

La migración elimina los valores de las cuatro columnas retiradas. Antes de actualizar una base habitual, conservar un respaldo completo anterior al cambio y comprobar su restauración en una instancia separada. Para recuperar esos valores, restaurar el respaldo en otra base y verificarla con el contrato anterior. Coordinar el cambio de instancia con los escritores detenidos y reconciliar cualquier escritura posterior al respaldo antes de reanudar.

## Evidencia de la rama

Base `56a2697`. PostGIS 16 y Redis 7 aislados. La instalación limpia pasó `prisma db init` y `prisma db verify` tras ejecutar los SQL de arranque. En una segunda base, se sembraron dos revisiones publicadas de agosto de 2026 con un movimiento AER → CBA por revisión y una sola publicación vigente. Se compararon los movimientos, ejecuciones, revisiones, publicación y metadatos de fuente antes y después del recorte. Las cuatro columnas desaparecieron y las filas y relaciones comparadas coincidieron. El respaldo anterior se restauró en una tercera base con `pg_dump` y `pg_restore` de PostgreSQL 16, recuperó los cuatro valores sintéticos de ambos movimientos y pasó `prisma db verify` con el contrato anterior.

- Backend: `npm run build`, `npm run lint` y `npm test -- --runInBand`. 210 pruebas aprobadas en 39 suites. ESLint salió con código 0 y el generador Prisma informó sus avisos sobre nombres SQL existentes.
- Frontend: `npm run build` y `npm test`. 229 pruebas aprobadas en 38 suites. `nuxi typecheck` requiere un verificador Vue que el proyecto no tiene instalado.
- E2E: `npm run test:e2e -- --runInBand --runTestsByPath test/actividad-anac.e2e-spec.ts test/actividad-anac-jobs.e2e-spec.ts test/contexto-ruta.e2e-spec.ts test/eurocontrol.e2e-spec.ts test/pipelines.e2e-spec.ts`. 5 suites aprobadas con CSV, XLSX y muestras de auditoría sintéticos.
- La revisión independiente detectó que la API y exportación genérica de ETL todavía exponían muestras ANAC legadas. Se corrigió la respuesta y la suite de pipelines verifica la omisión del contenido original.
- Navegador: inicio de sesión con una cuenta sintética en el build de producción, lectura de la publicación de octubre de 2026 y consulta de conectividad con teclado. En un viewport de 390 px las tablas siguieron accesibles y la página no desbordó horizontalmente. La consola no registró mensajes de hidratación durante el recorrido. La tarjeta pública se comprobó en el E2E HTTP y en las pruebas de componente.

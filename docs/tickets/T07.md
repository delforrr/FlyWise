### Inventario de columnas

| Columna | Decisión y verificación |
| --- | --- |
| `aeropuertos.id_openflights`, `aerolineas.id_openflights` | Se trasladan a correspondencias por fuente e identificador. La migración compara cada vínculo antes de habilitar el retiro. La reingesta de ofertas usa las correspondencias y conserva PK y FK. |
| `aeropuertos.cantidad_rutas` | Se retira el contador. Las consultas obtienen el total de rutas dirigidas vigentes con oferta vigente. La búsqueda calcula el orden sin caché de resultados. |
| `pais_id` y `vinculo_pais_inferido` | Se conservan. El primero vincula al país canónico. El segundo permite corregir un enlace inferido sin reemplazar una decisión administrativa. |
| `nombre_pais` de aeropuerto, `pais` de aerolínea | Se conservan por compatibilidad con localización y reconciliación de nombres. La observación externa registra por separado el texto recibido, incluyendo nombres sin correspondencia. Para cargas antiguas, el backfill conserva el texto canónico disponible al migrar. |
| `fuente` | La fuente canónica sigue indicando la procedencia del dato visible y la precedencia de OurAirports. La fuente de la correspondencia identifica el espacio de IDs externos. Ambas se conservan. |
| `latitud`, `longitud`, `ubicacion` | Se conservan para la API y las búsquedas con PostGIS. El backend las escribe juntas en SRID 4326. |
| `protegido_manualmente`, `archivado_en`, `activa` | Se conservan. Controlan respectivamente la edición administrativa, la visibilidad del catálogo y el estado operativo informado. |

### Actualización y recuperación

Para una base existente con el modelo en español y la migración OTP aplicada:

1. Respaldar la base y ensayar la actualización y restauración sobre una copia descartable. Pausar escrituras del catálogo durante el cambio de versión.
2. Aplicar las expansiones `20261114_horarios_operaciones.sql`, `20261114_catalogo_consultas.sql` y `20261114_catalogo_identidades.sql` con `psql -v ON_ERROR_STOP=1 -f`. El último script comprueba cada ID histórico y revierte la transacción si hay correspondencias incompatibles.
3. Con la versión nueva, verificar reingesta y consultas. Las columnas antiguas permanecen disponibles para recuperación mientras se valida el corte, y la versión nueva deja de escribirles.
4. Aplicar `20261114_catalogo_contraccion.sql` cuando los consumidores ya lean las correspondencias y el conteo derivado. Validar con `npx prisma db verify --schema-only --db "$DATABASE_URL"`, firmar con `npx prisma db sign --db "$DATABASE_URL"` y repetir la verificación completa. Para volver a la versión anterior después de la contracción, restaurar el respaldo en una instancia separada y verificar relaciones y recuentos antes de reconectar. Reconciliar las escrituras posteriores al respaldo antes de retomar servicio.

En una base nueva, el contrato Prisma crea las tablas de correspondencias y la columna de horarios. Instalar la vista con el script de consultas después de inicializar el esquema.

### Evidencia de cierre

Rama `refactor/catalogo-generico` sobre `5d28cbd`. En la base descartable se verificaron 7.698 correspondencias de aeropuertos y 6.161 de aerolíneas antes de retirar las columnas. El ensayo por etapas con un catálogo sintético conservó la relación ruta–oferta–operadora, los IDs internos y una identidad OurAirports pendiente. `prisma db verify` confirmó marcador y esquema después de firmar la migración manual.

El gate pasó build de backend y frontend, ESLint sin errores ni advertencias, 210 pruebas backend, 229 frontend y 60 E2E. Los recorridos incluyen reingesta de OpenFlights, precedencia de OurAirports, concurrencia con edición y archivo, países sin resolver y catálogo público. El E2E del contador falló primero contra el valor mutable y pasó con el conteo en consulta. Logs en `/tmp/flywise-t07-*.log`.

La revisión de estándares y Ponytail separó el transporte de la resolución transaccional, eliminó la caché del orden de búsqueda y simplificó el despacho de escrituras por catálogo. La revisión de especificación detectó pérdida de conteo en lecturas anidadas, colisiones entre códigos complementarios, observaciones pendientes desactualizadas y contracción prematura. Se corrigieron y se repitieron los recorridos afectados. T08 queda desbloqueado.
